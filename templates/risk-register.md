# Risk Register Template

## 🎯 Purpose
A risk register helps teams identify, assess, and manage risks that could impact delivery.  
It provides visibility, accountability, and proactive mitigation strategies.

---

## 📑 Structure

| Risk ID | Description | Impact (H/M/L) | Likelihood (H/M/L) | Owner | Mitigation Plan | Status |
|---------|-------------|----------------|--------------------|-------|-----------------|--------|
| R-001 | Key dependency on external API availability | High | Medium | Alice | Establish fallback caching mechanism | Open |
| R-002 | Delays in hiring critical backend engineer | Medium | High | Bob | Engage contractors as interim solution | Monitoring |
| R-003 | Security vulnerability in legacy module | High | Low | Security Team | Patch scheduled in next sprint | Closed |

---

## ✅ Best Practices
- **Prioritize by impact & likelihood**: Focus on high/high risks first.  
- **Assign clear owners**: Every risk should have someone accountable.  
- **Update regularly**: Review in weekly program syncs.  
- **Track status**: Move risks through Open → Monitoring → Mitigated → Closed.  
- **Document learnings**: Capture how risks were resolved for future reference.

---

## 🚀 Usage
- Create a new markdown file or spreadsheet for each major project.  
- Review risks at the start of each milestone.  
- Share register with stakeholders for transparency.
